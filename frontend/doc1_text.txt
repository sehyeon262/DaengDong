1. 이 문서를 읽기 전에
이 문서는 우리 팀이 Kotlin으로 Android 앱을 개발할 때 지켜야 할 규칙을 정리한 것입니다.
팀원 모두가 코틀린을 처음 사용하기 때문에, 최대한 쉽게 설명하겠습니다.

팀원 누구의 코드를 봐도 같은 구조, 같은 네이밍, 같은 흐름으로 작성되어 있어야 합니다. 이 문서대로 따라하면 됩니다.
왜 컨벤션이 필요한가?
4명이 각자 다른 방식으로 코드를 짜면 나중에 합칠 때 충돌이 생기고, 다른 사람 코드를 이해하기 어렵습니다. 같은 규칙을 따르면 &quot;내 코드&quot;와 &quot;남의 코드&quot;의 차이가 없어집니다.

3. 아키텍처 개요
3-1. Clean Architecture란?
앱의 코드를 &quot;역할별로 나눠서 관리&quot;하는 방법입니다. 마치 회사에서 부서를 나누는 것처럼, 코드도 역할에 따라 나눕니다.

Model - View - ViewModel 의 약자입니다.

💡 왜 이렇게 나누나요?
각 부분이 독립적이기 때문에 한 곳을 수정해도 다른 곳에 영향을 주지 않습니다. 예를 들어 UI 디자인을 바꿔도 데이터 처리 로직은 그대로입니다.
4. 데이터 흐름 (가장 중요!)
이 섹션이 가장 중요합니다. 모든 기능은 반드시 이 순서를 따릅니다.
4-1. 요청 흐름 (사용자 → 서버)
  사용자가 버튼 클릭
       ↓
  Screen (UI)        →  사용자 입력을 받아서 ViewModel에 전달
       ↓
  ViewModel          →  UseCase를 호출
       ↓
  UseCase            →  Repository를 호출
       ↓
  Repository         →  API를 호출하거나 로컬 데이터에 접근
       ↓
  API (Retrofit)     →  서버에 HTTP 요청 전송
       ↓
  Spring Boot 서버   →  요청 처리 후 응답 반환
4-2. 응답 흐름 (서버 → 사용자)
결과는 반대 방향으로 올라옵니다.
  Spring Boot 서버   →  JSON 응답 반환
       ↓
  API (Retrofit)     →  JSON을 Kotlin 객체로 변환
       ↓
  Repository         →  필요하면 로컬에도 저장
       ↓
  UseCase            →  결과를 그대로 전달
       ↓
  ViewModel          →  UI 상태 업데이트
       ↓
  Screen (UI)        →  화면에 결과 표시
4-3. 한 줄 정리
  요청: UI → ViewModel → UseCase → Repository → API → Server
  응답: Server → API → Repository → UseCase → ViewModel → UI
⚠️ 절대 규칙
이 순서를 건너뛰면 안 됩니다! UI에서 직접 API를 호출하거나, ViewModel에서 직접 Repository를 호출하면 안 됩니다. 반드시 UseCase를 거쳐야 합니다.

6. 각 폴더/파일의 역할 상세 설명
6-1. data/ (데이터 계층)
실제 데이터를 가져오고 저장하는 곳입니다. 서버와 통신하거나, 앱 내부에 데이터를 저장합니다.
data/remote/ — 서버 API 인터페이스
서버와 통신하기 위한 인터페이스를 정의합니다. Retrofit이 이 인터페이스를 보고 자동으로 HTTP 요청을 만들어줍니다.
비유: 
식당의 &quot;메뉴판&quot;입니다. &quot;이런 음식 주세요&quot;라고 적어두면, Retrofit(웨이터)이 알아서 주방(서버)에 주문합니다.
data/local/ — 앱 내부 저장소
앱이 꺼져도 유지되어야 하는 데이터를 저장합니다. 예를 들어 로그인 토큰은 앱을 다시 켰을 때도 있어야 하므로 여기에 저장합니다.
비유: 
집의 &quot;금고&quot;입니다. 중요한 것(토큰, 설정값)을 넣어두면 다음에도 꺼내 쓸 수 있습니다.
data/repository/ — 데이터 관리자
데이터를 어디서 가져올지 판단하는 곳입니다. 서버에서 가져올지, 로컬에서 가져올지 결정합니다. API를 직접 호출하고, 필요하면 로컬에도 저장합니다.
비유: 
물류 관리자입니다. &quot;재고(캐시)가 있으면 창고에서, 없으면 공장(서버)에서 가져와라&quot;고 지시합니다.
6-2. domain/ (비즈니스 로직 계층)
앱의 핵심 기능과 데이터 모델을 정의하는 곳입니다. Android에 의존하지 않는 순수 Kotlin 코드입니다.
domain/model/ — 데이터 모델
앱에서 사용하는 데이터의 형태를 정의합니다. data class로 작성합니다.
비유: 
&quot;주문서 양식&quot;입니다. 어떤 정보가 필요한지 정해놓은 틀입니다.
domain/usecase/ — 비즈니스 로직
앱의 기능 하나하나를 담당합니다. 한 UseCase는 딱 한 가지 기능만 합니다.
비유: 
&quot;작업 지시서&quot;입니다. &quot;로그인해라&quot;, &quot;사용자 목록 가져와라&quot; 같은 구체적인 작업 하나만 수행합니다.
6-3. ui/ (UI 계층)
사용자가 직접 보고 상호작용하는 화면 계층입니다.
ui/screen/ — 각 화면
기능(feature) 단위로 폴더를 만들고, 그 안에 Screen, ViewModel, State 파일을 넣습니다.
비유: 
앱의 각 &quot;페이지&quot;입니다. 로그인 페이지, 홈 페이지 등 사용자가 보는 화면 하나하나입니다.
ui/component/ — 재사용 컴포넌트
여러 화면에서 반복 사용되는 UI 조각입니다. 버튼, 카드, 다이얼로그 등을 여기에 만들어두고 가져다 씁니다.
ui/theme/ — 디자인 설정
앱 전체의 색상, 폰트, 스타일을 정의합니다. Color.kt, Theme.kt, Type.kt 파일이 들어갑니다.
6-4. navigation/ — 화면 이동
어떤 화면에서 어떤 화면으로 이동할지 관리합니다. Route(경로)를 상수로 정의하고, NavGraph에서 화면 이동 구조를 설정합니다.
6-5. di/ — 의존성 주입 (Hilt)
Hilt가 객체를 자동으로 만들어서 넣어주도록 설정하는 곳입니다.
비유: 
&quot;인사팀&quot;입니다. 어떤 부서(클래스)에 어떤 사람(객체)을 배치할지 정해줍니다. 우리가 직접 new 로 객체를 만들 필요가 없어집니다.
6-6. util/ — 공통 유틸리티
여러 곳에서 사용되는 상수값, 확장 함수, 날짜 변환 등 공통 유틸을 모아둡니다.
6-7. MainActivity.kt — 앱 시작점
앱이 실행될 때 가장 먼저 실행되는 Activity입니다. setContent에서 Theme과 NavGraph를 호출합니다.
6-8. MyApplication.kt — Hilt 초기화
@HiltAndroidApp 어노테이션을 붙여서 Hilt를 초기화합니다. 이 파일이 없으면 Hilt가 동작하지 않습니다.
7. 기능 구현 순서
새 기능을 만들 때 어떤 파일부터 작성해야 하는지 순서입니다.
아래에서 위로, 즉 데이터 쪽부터 만드는 것이 좋습니다.
⚠️ 왜 이 순서인가요?
위(UI)부터 만들면 아래(데이터)가 없어서 테스트할 수 없습니다. 아래부터 만들면 각 단계를 만들면서 바로 테스트할 수 있습니다.
Step 1. Model 작성 (domain/model/)
먼저 이 기능에서 사용할 데이터의 형태를 정합니다.
  // domain/model/LoginResult.kt
  data class LoginResult(
      val accessToken: String
  )
Step 2. API 인터페이스 작성 (data/remote/)
서버에 어떤 요청을 보낼지 정의합니다.
  // data/remote/AuthApi.kt
  interface AuthApi {
      @POST(&quot;auth/login&quot;)
      suspend fun login(
          @Body request: LoginRequest
      ): LoginResponse
  }
Step 3. Repository 작성 (data/repository/)
API를 호출하고, 필요하면 로컬에도 데이터를 저장합니다.
  // data/repository/AuthRepository.kt
  class AuthRepository @Inject constructor(
      private val api: AuthApi,
      private val tokenDataStore: TokenDataStore
  ) {
      suspend fun login(email: String, password: String) {
          val response = api.login(LoginRequest(email, password))
          tokenDataStore.saveToken(response.accessToken)
      }
  }
Step 4. UseCase 작성 (domain/usecase/)
비즈니스 로직을 작성합니다. Repository를 호출합니다.
  // domain/usecase/LoginUseCase.kt
  class LoginUseCase @Inject constructor(
      private val repository: AuthRepository
  ) {
      suspend operator fun invoke(
          email: String,
          password: String
      ) {
          repository.login(email, password)
      }
  }
Step 5. State 작성 (ui/screen/[feature]/)
이 화면의 상태를 정의합니다.
  // ui/screen/login/LoginState.kt
  data class LoginState(
      val isLoading: Boolean = false,
      val isSuccess: Boolean = false,
      val error: String? = null
  )
Step 6. ViewModel 작성 (ui/screen/[feature]/)
UseCase를 호출하고, 결과에 따라 State를 업데이트합니다.
  // ui/screen/login/LoginViewModel.kt
  @HiltViewModel
  class LoginViewModel @Inject constructor(
      private val loginUseCase: LoginUseCase
  ) : ViewModel() {
      private val _state = MutableStateFlow(LoginState())
      val state = _state.asStateFlow()
      fun login(email: String, password: String) {
          viewModelScope.launch {
              _state.update { it.copy(isLoading = true) }
              try {
                  loginUseCase(email, password)
                  _state.update { it.copy(isLoading = false, isSuccess = true) }
              } catch (e: Exception) {
                  _state.update { it.copy(isLoading = false, error = e.message) }
              }
          }
      }
  }
Step 7. Screen 작성 (ui/screen/[feature]/)
마지막으로 사용자가 볼 화면을 만듭니다.
  // ui/screen/login/LoginScreen.kt
  @Composable
  fun LoginScreen(
      viewModel: LoginViewModel = hiltViewModel(),
      navController: NavController
  ) {
      val state by viewModel.state.collectAsState()
      // state에 따라 UI 표시
      Button(onClick = { viewModel.login(email, password) }) {
          Text(&quot;로그인&quot;)
      }
  }
Step 8. DI 모듈에 등록 (di/)
Hilt가 새로 만든 클래스들을 알 수 있도록 모듈에 등록합니다.
Step 9. Navigation에 추가 (navigation/)
새 화면을 NavGraph에 추가합니다.
💡 요약: 구현 순서
Model → API → Repository → UseCase → State → ViewModel → Screen → DI 등록 → Navigation 추가

10. ViewModel 작성법
10-1. ViewModel의 역할
UI의 상태(State)를 관리합니다
UseCase를 호출합니다 (Repository 직접 호출 금지!)
Navigation 이벤트를 처리합니다
10-2. 기본 템플릿
  @HiltViewModel
  class [Feature]ViewModel @Inject constructor(
      private val [feature]UseCase: [Feature]UseCase
  ) : ViewModel() {
      // UI 상태
      private val _state = MutableStateFlow([Feature]State())
      val state = _state.asStateFlow()
      // 기능 실행
      fun doSomething(param: String) {
          viewModelScope.launch {
              _state.update { it.copy(isLoading = true) }
              try {
                  [feature]UseCase(param)
                  _state.update { it.copy(isLoading = false, isSuccess = true) }
              } catch (e: Exception) {
                  _state.update { it.copy(isLoading = false, error = e.message) }
              }
          }
      }
  }
⚠️ ViewModel 규칙
ViewModel은 절대로 Repository를 직접 호출하면 안 됩니다. 반드시 UseCase를 통해서만 데이터에 접근합니다.
11. UseCase 작성법
11-1. UseCase의 역할
UseCase는 딱 한 가지 기능만 담당합니다. &quot;로그인&quot;, &quot;사용자 목록 가져오기&quot; 등 구체적인 작업 하나입니다.
11-2. 기본 템플릿
  class [Action][Target]UseCase @Inject constructor(
      private val repository: [Feature]Repository
  ) {
      suspend operator fun invoke(params...) {
          return repository.doSomething(params...)
      }
  }
💡 operator fun invoke란?
invoke를 사용하면 UseCase를 함수처럼 호출할 수 있습니다. loginUseCase.invoke(email, password) 대신 loginUseCase(email, password)로 간단하게 쓸 수 있습니다.
12. Repository 작성법
12-1. Repository의 역할
API를 직접 호출합니다
로컬 데이터를 저장/조회합니다
서버 데이터와 로컬 데이터 중 어디서 가져올지 결정합니다
12-2. 기본 템플릿
  class [Feature]Repository @Inject constructor(
      private val api: [Feature]Api,
      private val localDataStore: [Feature]DataStore  // 필요한 경우
  ) {
      suspend fun doSomething(params...): Result {
          val response = api.apiCall(params...)
          localDataStore.save(response)  // 필요한 경우
          return response
      }
  }
13. API (Retrofit) 작성법
13-1. 기본 규칙
API는 반드시 interface로 작성합니다
모든 함수에 suspend를 붙입니다 (비동기 처리)
어노테이션으로 HTTP 메서드를 지정합니다 (@GET, @POST, @PUT, @DELETE)
13-2. 기본 템플릿
  interface [Feature]Api {
      @GET(&quot;endpoint&quot;)
      suspend fun getItems(): List&lt;Item&gt;
      @POST(&quot;endpoint&quot;)
      suspend fun createItem(
          @Body request: CreateItemRequest
      ): ItemResponse
      @PUT(&quot;endpoint/{id}&quot;)
      suspend fun updateItem(
          @Path(&quot;id&quot;) id: Int,
          @Body request: UpdateItemRequest
      ): ItemResponse
      @DELETE(&quot;endpoint/{id}&quot;)
      suspend fun deleteItem(
          @Path(&quot;id&quot;) id: Int
      )
  }

전체 동작 순서
사용자가 로그인 버튼을 누르면 내부에서 이런 순서로 처리됩니다.
  1. LoginScreen      — 사용자가 이메일/비밀번호 입력 후 버튼 클릭

  3. LoginUseCase     — Repository 호출
  4. AuthRepository   — API 호출 + 토큰 저장
  5. AuthApi          — 서버에 POST /auth/login 요청
  6. Spring Boot      — 비밀번호 검증, JWT 토큰 생성
  7. 응답 반환         — JWT 토큰이 역순으로 올라옴
  8. TokenDataStore   — Repository가 토큰을 로컬에 저장
  9. ViewModel        — State를 isSuccess = true로 변경
  10. Navigation      — LoginScreen → HomeScreen 이동

  @HiltViewModel
  class LoginViewModel @Inject constructor(
      private val loginUseCase: LoginUseCase
  ) : ViewModel() {
      private val _state = MutableStateFlow(LoginState())
      val state = _state.asStateFlow()
      fun login(email: String, password: String) {
          viewModelScope.launch {
              _state.update { it.copy(isLoading = true) }
              try {
                  loginUseCase(email, password)
                  _state.update {
                      it.copy(isLoading = false, isSuccess = true)
                  }
              } catch (e: Exception) {
                  _state.update {
                      it.copy(isLoading = false, error = e.message)
                  }
              }
          }
      }
  }

  @Composable
  fun LoginScreen(
      viewModel: LoginViewModel = hiltViewModel(),
      navController: NavController
  ) {
      val state by viewModel.state.collectAsState()
      var email by remember { mutableStateOf(&quot;&quot;) }
      var password by remember { mutableStateOf(&quot;&quot;) }
      // 로그인 성공 시 화면 이동
      LaunchedEffect(state.isSuccess) {
          if (state.isSuccess) {
              navController.navigate(Routes.HOME) {
                  popUpTo(Routes.LOGIN) { inclusive = true }
              }
          }
      }
      Column {
          TextField(
              value = email,
              onValueChange = { email = it },
              label = { Text(&quot;이메일&quot;) }
          )
          TextField(
              value = password,
              onValueChange = { password = it },
              label = { Text(&quot;비밀번호&quot;) },
              visualTransformation = PasswordVisualTransformation()
          )
          CustomButton(
              text = &quot;로그인&quot;,
              onClick = { viewModel.login(email, password) },
              isLoading = state.isLoading
          )
          state.error?.let { Text(it, color = Color.Red) }
      }
  }
